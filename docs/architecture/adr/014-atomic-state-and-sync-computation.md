# ADR-014 原子状态保存与同步计算

适用于 develop 7.0，扩展 ADR-009 和 ADR-013 的本地保存及计算执行路径。

## 状态提交

StateService 在 StorageMutationCoordinator 的共享锁内读取和准备变更。支持 `commitLockedBatch` 的 IndexedDB 端口将业务域、已提交活动记录、同步待处理证明与启用的备份计数写入同一个原生事务，以事务 complete 确认成功。准备阶段完成全部异步工作，原生事务中只排队存储请求。

端口在尝试写入前确认能力不可用时返回 false，调用方进入既有 schema 2 日志路径。其他异常按事务中止处理。启动与写入前恢复既有日志，成功后的缓存与通知失败按已提交语义处理。数据保存在既有 JAV-JHS/appData 业务键中，备份和远端同步遵循现有格式。

事务在活动阶段排队全部请求，并以 complete 作为持久化成功边界。事务生命周期依据 [IndexedDB 事务规范](https://www.w3.org/TR/IndexedDB-2/#transaction-lifetime)。

## 同步计算

SyncComputation 由 Composition Root 持有，首次任务惰性创建单个内嵌 Worker。投影、差异、合并、物化及 JSON 编解码复用纯计算模块。设置语义校验、网络、凭证和存储提交继续由原服务执行。线程创建受限、启动超过两秒或传输失败时采用 4ms 协作计算。任务取消或运行时结束释放线程，调用方提交前重新检查存储版本、连接及生命周期。

状态显示与调度采用经 pending ledger 四字段验证的轻量元数据缓存。每轮传输保留完整漏写核对，轮内快照复用沿用现有进度证明与失效规则。

数据库所属的同步模型按元数据版本复用，业务域每轮重新读取。Worker 只在四字段版本证明匹配时复用核对输入及已确认比较基线，收到的新业务数据仍执行完整差异检查。取消、连接切换及停用释放线程与快照，迟到读取按代次拒绝回填缓存。

首次填充可复用模型及元数据缓存时持有共享存储锁，避免将已经推进的 ledger 版本与尚未写完的 sidecar 绑定。普通兼容读取保持原有返回契约，仅作为本次读取结果使用。线程重建后忽略旧线程的迟到消息及错误。Blob Worker 的创建与受限回退参考 [Worker 构造器文档](https://developer.mozilla.org/en-US/docs/Web/API/Worker/Worker)。

成功轮询的检查时间与恢复状态写入本地 pending ledger 的可选检查证明，按其对应的 sidecar 元数据版本叠加读取。后续错误、恢复和模型写入推进元数据版本，使旧检查证明失效。普通轮询据此更新小记录，完整模型仍按原有 schema 1 契约存储。

## 验证

验证原子事务中止与重试、日志恢复、撤销资格、同步证明、备份计数、原生 Worker 与受限回退、未来版本及取消。性能分别测量一万条常规库和五万条压力库，统计交互与总内存。历史性能参考值与同环境 HEAD 对照分别报告。
